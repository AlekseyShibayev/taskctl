# SPEC — taskctl: очередь create/get на goqite

| Поле | Значение |
|---|---|
| Статус | accepted |
| Версия | 6 |
| Дата | 2026-11-17 |
| Код | `internal/store`, `internal/mcp`, `cmd/taskctl` |

## 1. Что это

`taskctl` — локальная очередь задач для агента: один бинарник, MCP-сервер
поверх stdio, SQLite в домашнем каталоге, без сети. ОС — Linux, один
пользователь. Хранилище — `maragu.dev/goqite` v0.4.0 поверх
`modernc.org/sqlite`.

Цель: текст, положенный один раз, выдаётся не более одного раза — при
параллельных вызовах, нескольких процессах и после перезапуска.

## 2. Границы

**In scope:** команда `taskctl mcp`; инструменты `create(text)` и `get()`;
путь к файлу БД; кадры JSON-RPC, `initialize` и `tools/list`.

**Out of scope:** сеть; статусы задач; lease, таймауты и возврат задачи в
очередь; удаление, редактирование, дедупликация; список и пагинация;
миграции схемы; прочий CLI; журналирование; отказы ФС и ОС; ограничения на
длину текста; сигнальный shutdown.

**Ограничения:** Go, один бинарник без cgo, только stdio.

## 3. Поведение

| Метод | Аргумент | Результат |
|---|---|---|
| `create(text)` | `text` | `void`: успешный вызов возвращает `content: []` |
| `get()` | нет | `string`: текст задачи в `content[0].text` |

### `create(text) -> void`

1. `text` обязателен: аргумент отсутствует или равен `null` — ошибка
   инструмента `text is required`; `text` не строка или лишнее поле —
   `-32602`.
2. Текст хранится как передан, без TrimSpace и нормализации; тело
   сообщения goqite — его байты в UTF-8.
3. Ответ — успешный tool-результат с пустым `content`; текст и
   идентификатор не возвращаются.
4. Дедупликации нет: одинаковый текст, положенный дважды, — два сообщения.

### `get() -> string`

1. Аргументов нет: отсутствие `arguments`, `null` и `{}` равнозначны;
   любое поле в аргументах — `-32602`.
2. Берётся следующее сообщение goqite: `priority desc, created`.
   Приоритет всегда 0, порядок — по `created` с точностью до миллисекунды.
3. Получение и удаление — одна транзакция (`ReceiveTx` + `DeleteTx`).
   Успешный `get` удаляет сообщение; повторно оно не выдаётся.
4. Возвращается тело сообщения как текст в `content[0].text`, не JSON.
5. Свободных сообщений нет — ошибка инструмента
   `queue is empty: every task has been taken`.

### Протокол

- Транспорт — stdio, один JSON-RPC 2.0 объект на строку (UTF-8, `\n`).
- `initialize` отвечает `protocolVersion` = `2025-06-18` и возможностью
  `tools`; `tools/list` возвращает `create` и `get`.
- Рукопожатие не проверяется: `tools/list` и `tools/call` работают и до
  `initialize`.
- Невалидный JSON — `-32700`; неизвестный метод — `-32601`; ошибка
  аргументов и неизвестный инструмент — `-32602`. Поток после ошибки
  продолжает работу.
- Сообщение без `id` — notification: ответа нет, побочного эффекта нет.

## 4. Инварианты

| ID | Утверждение |
|---|---|
| INV-1 | Успешный `get` удаляет сообщение в той же транзакции; повторно оно не выдаётся. |
| INV-2 | N параллельных `get` на M свободных сообщениях дают min(N, M) успехов, остальные — ошибку пустой очереди; ни одно сообщение не выдано дважды. |
| INV-3 | `create` не меняет уже стоящие сообщения; `get` только удаляет одно. |
| INV-4 | Пустая очередь — всегда ошибка; текст задачи не может быть принят за сигнал пустоты. |
| INV-5 | `create` вернул успех ⇒ сообщение закоммичено и видно следующему `get`, в том числе другому процессу. |
| INV-6 | `create` не возвращает содержимого; `get` возвращает только текст задачи. |

## 5. Данные

`$XDG_DATA_HOME/taskctl/tasks.db`, иначе
`~/.local/share/taskctl/tasks.db`; создаётся при первом открытии. Каталог —
`0700`, файл — `0600`. SQLite в режиме WAL, `busy_timeout` 5000 мс, одно
соединение на процесс. Таблица `goqite` создаётся по `schema_sqlite.sql` из
`maragu.dev/goqite` v0.4.0; текст задачи — колонка `body`.

```json
{"content":[]}
```

```json
{"content":[{"type":"text","text":"починить сборку"}]}
```

Ошибки инструмента (`text is required`, пустая очередь) — `isError: true`,
текст в `content[0].text`. Ошибки аргументов и неизвестный инструмент —
JSON-RPC `-32602`.

## 6. Критерии приёмки

| ID | Проверка | Тест |
|---|---|---|
| ACC-1 | `create` → `get`: тот же текст; второй `get` — ошибка пустой очереди | `TestCreateAndGet` |
| ACC-2 | `get` возвращает только текст, не JSON-объект | `TestGetReturnsPlainText` |
| ACC-3 | 40 параллельных `get` из двух `Store` на 20 сообщениях → 20 успехов, 20 пустых ответов, ни один текст не выдан дважды | `TestGetIsAtomic` |
| ACC-4 | Сообщения выдаются от старейшего | `TestGetOldestFirst` |
| ACC-5 | После перезапуска взятое сообщение не выдаётся | `TestGetSkipsTaken` |
| ACC-6 | Текст возвращается байт в байт (пробелы, эмодзи) | `TestCreateKeepsTextAsSent` |
| ACC-7 | Одинаковый текст, положенный дважды, — два сообщения | `TestNoDeduplication` |
| ACC-8 | `create` с лишним полем, нестроковым `text`, `get` с аргументами, неизвестный инструмент → `-32602`, очередь не меняется | `TestBadArguments` |
| ACC-9 | `create` без `text` → ошибка инструмента, сообщение не ставится | `TestBadArguments` |
| ACC-10 | `initialize` → `2025-06-18` и `tools`; `tools/list` → ровно `create` и `get` | `TestInitializeAndToolsList` |
| ACC-11 | `tools/call` без `id` не меняет очередь и не получает ответа | `TestNotificationHasNoEffect` |
| ACC-12 | Невалидный JSON → `-32700`, поток продолжает работу | `TestParseErrorKeepsStream` |
| ACC-13 | Неизвестный метод → `-32601` | `TestUnknownMethod` |
| ACC-14 | `taskctl mcp` обслуживает `create`/`get` через stdio | `TestStdioSmoke`, `TestMCPCommand` |
| ACC-15 | Пустой ввод — нет ответов, нет ошибки | `TestEmptyInput` |
| ACC-16 | Относительный путь к БД работает | `TestRelativePath` |
